\section{What ran, and what is left}
\label{app:plan}

The design planned for 52 nodes; \cref{sec:machine} says why the runs so far stop at about 39--43, and why all 52 can be used since November~6. \Cref{tab:progress} counts planned points: a configuration at a node count, repetitions not counted. Failed: the run failed and the failure answers the question, so the point counts as done (for example, out of memory). Points that need 50 or more nodes count apart. \textbf{A compromise} is a test at a smaller scale than the design planned, or one holding the 3 slow nodes when a run of that size could avoid them. Full experiments at 52 nodes also counted until the slow nodes were fixed on November~6. A quick 52-node run that checks it works does not fill the 50+ column. Compromises count apart too. Those already made stand in this report, such as the runs at 39 nodes that replace the design's 52. Those not yet made go last of all. The plan is the design's, as the launchers carry it, changed as results came in: 48k tokens per GPU with selective recompute was skipped, for memory, and \texttt{pp10-ep8} and \texttt{pp25-ep8} were added to fit 40 and 50 nodes. The network tests stopped at 25 nodes, the job limit then, with one D3 at 26 later, so D4 did not run; the plan takes D2--D4 to 52 nodes as the design has it.
